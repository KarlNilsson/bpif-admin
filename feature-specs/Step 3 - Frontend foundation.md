# Plan: Frontend foundation (step 3)

## Context

Step 3 of `Implementation.md` turns the frontend skeleton into a base that the feature steps (5–7) build pages on:

- shadcn-svelte with Tailwind, and an app shell
- a complete, typed API client
- types generated from the backend's OpenAPI schema
- shared formatting helpers
- lint rules matching the code conventions
- a CI workflow for both applications

The frontend currently uses SvelteKit 3, Svelte 5, Vite 8, TypeScript 6 and ESLint 10. The Kit config (adapter-static
with `fallback: 'index.html'`) lives in `vite.config.ts`, and imports use the `#lib/...` subpath imports from
`package.json`, not `$lib`. There's a minimal `lib/api/client.ts` (`request<T>()`), a hand-written `Health` type and a
health page at `/`. There's no Tailwind, no shadcn-svelte and no `.github/`.

Decisions made:

- **UI language is Swedish.** All user-facing text is written in Swedish in the frontend. The API, code and comments
  stay in English. The frontend maps API errors to Swedish messages itself, and never shows the backend's English
  `detail` text directly.
- **Route groups from the start.** Public pages live in `src/routes/(public)/` and admin pages in
  `src/routes/(admin)/`. The groups don't change URLs. They give each audience its own layout, and step 4 a single
  place for its guard (`(admin)/+layout.ts`). This step creates `(public)`. Step 5 adds `(admin)`.
- **Types come from a running backend in development, and from a file in CI.** `npm run generate:types` reads the
  schema through the Vite proxy. CI exports it from the backend code with a small script and fails if the committed
  types are out of date.

## 1. Tailwind and shadcn-svelte

1. `npx sv add tailwindcss` installs Tailwind 4 with the Vite plugin, and `src/app.css` imported from the root
   layout.
2. `npx shadcn-svelte@latest init` writes `components.json` and the theme variables in `app.css`. Pick a neutral base
   color. Set the aliases to match the project's import style:

   ```json
   "aliases": {
     "components": "#lib/components",
     "ui": "#lib/components/ui",
     "utils": "#lib/utils/cn",
     "hooks": "#lib/hooks",
     "lib": "#lib"
   }
   ```

   `cn` goes in `lib/utils/cn.ts` rather than shadcn's default `lib/utils.ts`, because `lib/utils/` is a folder of
   helpers in this project (`CLAUDE.md`).
3. Add the base components:
   `npx shadcn-svelte@latest add button card badge input label select table alert alert-dialog dialog sonner separator`.
   Later steps add what they need (e.g. `checkbox` in step 5, `radio-group` in step 7).

**Import-resolution risk.** shadcn-svelte writes imports such as `#lib/utils/cn.js`, with a `.js` suffix. The project
maps `#lib/*` to `./src/lib/*` through `package.json` `imports`, and the existing code imports `.ts` files with their
extension. Check this right after `add`: run `npm run check` and `npm run build`. If the `.js` specifiers don't
resolve, fix it in configuration, for example by adding a `"#lib/*.js": "./src/lib/*.ts"` entry or by adjusting the
aliases. Never fix it by editing the generated files, which must stay updatable with the CLI.

## 2. App shell

- **`app.html`:** `<html lang="sv">`.
- **`routes/+layout.svelte`:** imports `app.css`, sets the favicon and renders `{@render children()}` followed by
  `<Toaster richColors />` from `#lib/components/ui/sonner`. Mutations in later steps report their result with
  `toast.success(...)` / `toast.error(...)`.
- **`routes/(public)/+layout.svelte`:** `SiteHeader` with the club name ("BPIF") and a narrow centred container
  (`max-w-xl`), suitable for a phone. That's where most payers will be.
- **`routes/(public)/+page.ts` / `+page.svelte`:** the existing health page, moved into the group. It's rendered as a
  `Card` with two rows, "API" and "Databas", showing "OK" / "Ej tillgänglig". The load function is unchanged. Step 7
  replaces this page with the payment form and moves the status card to `(admin)/status`.
- **`routes/+error.svelte`:** a `Card` showing `page.status` and a Swedish message (404: "Sidan hittades inte",
  otherwise "Något gick fel"), plus `page.error?.message` when it adds information, and a link "Till startsidan".
- **`lib/components/layout/SiteHeader.svelte`:** props `{ title: string; children?: Snippet }`. The optional snippet
  is where the admin layout (step 5) renders its navigation.

## 3. API client (`lib/api/client.ts`)

The shared wrapper is the only place that calls `fetch`. Domain modules (`lib/api/<domain>.ts`) wrap it in typed
functions, and components never import it directly.

```ts
export type Fetch = typeof fetch;
export type Query = Record<string, string | number | boolean | null | undefined>;

export interface ValidationIssue {
	loc: (string | number)[];
	msg: string;
	type: string;
}

export class ApiError extends Error {
	constructor(
		readonly status: number,
		readonly detail: string | ValidationIssue[] | undefined
	) { ... }
}

export const api = {
	get: <T>(fetchFn: Fetch, path: string, query?: Query) => request<T>(fetchFn, 'GET', path, { query }),
	post: <T>(fetchFn: Fetch, path: string, body?: unknown) => request<T>(fetchFn, 'POST', path, { body }),
	put: <T>(fetchFn: Fetch, path: string, body?: unknown) => request<T>(fetchFn, 'PUT', path, { body }),
	patch: <T>(fetchFn: Fetch, path: string, body?: unknown) => request<T>(fetchFn, 'PATCH', path, { body }),
	delete: <T = void>(fetchFn: Fetch, path: string) => request<T>(fetchFn, 'DELETE', path)
};
```

`request` does the following:

- Prefixes `/api/v1` and appends the query, skipping `null` / `undefined` values.
- Sends `Accept: application/json`. With a body, it also sends `Content-Type: application/json` and a JSON body.
- Returns `undefined` for 204 or an empty body. Otherwise it parses the JSON.
- On a non-2xx response, it tries to parse `{ detail }` and throws `ApiError(status, detail)`.

Load functions pass SvelteKit's `fetch`. Event handlers pass the global `fetch`.

Helpers in the same module:

- **`orNotFound<T>(promise: Promise<T>, message = 'Sidan hittades inte'): Promise<T>`** awaits the promise and turns
  an `ApiError` with status 404 into `error(404, message)` from `@sveltejs/kit`, so `+error.svelte` handles it. Load
  functions for `[id]` pages use it.
- **`errorMessage(e: unknown, overrides?: Partial<Record<number, string>>): string`** returns a Swedish message for
  toasts. `overrides[status]` comes first. Otherwise there's a default per status: 404 "Hittades inte", 409 "Ändringen
  krockar med befintliga uppgifter", 422 "Kontrollera uppgifterna i formuläret", 0 or network error "Kunde inte nå
  servern", otherwise "Något gick fel". Feature code passes context-specific overrides, e.g.
  `{ 409: 'Medlemsnumret används redan' }`.
- **`fieldErrors(e: unknown): Record<string, string>`** works on a 422 `ApiError` and maps each issue's `loc`, without
  the leading `'body'`, to a dotted key such as `'names.2'` or `'member_number'`, with the issue's `msg`. Forms use the
  keys to show their own Swedish message on the right field. They don't show `msg` directly, because it's English.

Step 4 adds its 401 handling (redirect to login) inside `request`. Nothing else needs to change for that.

`lib/api/health.ts` becomes `api.get<Health>(fetchFn, '/health')`.

## 4. Generated types

- `npm i -D openapi-typescript`.
- `package.json` script:

  ```json
  "generate:types": "openapi-typescript http://localhost:5173/api/v1/openapi.json -o src/lib/types/api.ts"
  ```

  The URL goes through the Vite dev server's `/api` proxy. It works the same from the host and from inside the
  frontend container (`docker compose exec frontend npm run generate:types`), as long as `docker compose up` is
  running.
- `src/lib/types/api.ts` is committed and never edited by hand. Regenerate it whenever a backend schema changes, in
  the same commit.
- `lib/types/<domain>.ts` re-exports friendly aliases, e.g.
  `export type Health = components['schemas']['HealthRead'];`. The hand-written `Health` interface is removed.
- **`backend/scripts/export_openapi.py`** writes `json.dumps(create_app().openapi(), indent=2)` to stdout. It needs
  `DATABASE_URL` to be set (any value: no connection is made, since the engine is created in the lifespan) and, from
  step 7, `SWISH_NUMBER`. CI uses it to check that the committed types match the backend (see 7).

## 5. Formatting (`lib/utils/format.ts`)

All currency and date presentation goes through these functions, so the app is consistent. The `Intl` instances are
created once at module level.

| Function                             | Example output       | Implementation                                                                                  |
| ------------------------------------ | -------------------- | ----------------------------------------------------------------------------------------------- |
| `formatCurrency(ore: number)`        | `300 kr`, `300,50 kr` | `Intl.NumberFormat('sv-SE', { style: 'currency', currency: 'SEK' })`, 0 decimals for whole kronor, 2 otherwise |
| `formatDate(value: string \| Date)`  | `2026-11-02`         | `Intl.DateTimeFormat('sv-SE', { dateStyle: 'short', timeZone: 'Europe/Stockholm' })`            |
| `formatDateTime(value: string \| Date)` | `2026-11-02 14:30` | `Intl.DateTimeFormat('sv-SE', { dateStyle: 'short', timeStyle: 'short', timeZone: 'Europe/Stockholm' })` |

The Stockholm time zone is fixed, because the club and its fees are in Sweden, whatever time zone the browser is in.
`Intl` puts a non-breaking space between the amount and "kr". That's intended.

## 6. ESLint

- `npm i -D @stylistic/eslint-plugin`. The deprecated core `quotes` rule isn't used.
- In `eslint.config.js`:
  - add `'@stylistic/quotes': ['error', 'single', { avoidEscape: true }]` to the shared rules block
  - add `src/lib/types/api.ts` to the ignores
  - turn off `@stylistic/quotes` for `src/lib/components/ui/**`, since the shadcn-svelte output uses double quotes. If
    generated components trigger other rules, ignore that folder entirely rather than editing generated files.
- HTML attribute quoting in `.svelte` markup is left to the `svelte/*` defaults.
- Scripts: `npm run lint` (existing `eslint .`) and `npm run check` (existing svelte-check) must both pass with no
  warnings.

## 7. CI (`.github/workflows/ci.yml`)

Runs on pushes to `master` and on pull requests. Action versions are pinned to a major version.

**`backend` job**

- A `postgres:18.6-alpine` service with `POSTGRES_USER/PASSWORD/DB` = `bpif` / `bpif-pw` / `bpif`, port 5432, and a
  `pg_isready` health option.
- `working-directory: backend`, and env:
  - `DATABASE_URL=postgresql+asyncpg://bpif:bpif-pw@localhost:5432/bpif`
  - `TEST_DATABASE_URL=postgresql+asyncpg://bpif:bpif-pw@localhost:5432/bpif_test`
- Steps:
  1. checkout
  2. `astral-sh/setup-uv`, with Python from `.python-version`
  3. `uv sync --frozen`
  4. `uv run autopep8 --diff --exit-code -r app tests alembic scripts`
  5. `uv run pytest`

**`frontend` job**

- `working-directory: frontend`.
- Steps:
  1. checkout
  2. `actions/setup-node` (Node 24, npm cache)
  3. `npm ci`, `npm run lint`, `npm run check`, `npm run build`
- API types drift check:
  1. `setup-uv`
  2. In `backend`, with dummy `DATABASE_URL` (and `SWISH_NUMBER` from step 7) env:
     `uv run python scripts/export_openapi.py > "$RUNNER_TEMP/openapi.json"`
  3. `npx openapi-typescript "$RUNNER_TEMP/openapi.json" -o src/lib/types/api.ts`
  4. `git diff --exit-code -- src/lib/types/api.ts`

**`docker` job**

- `cp .env.example .env`, then `docker compose -f docker-compose.yml -f docker-compose.production.yml build`. This
  catches Dockerfile breakage, such as a lockfile out of sync with `npm ci`, before deploying.

## Verification (definition of done)

1. `npm run lint`, `npm run check` and `npm run build` pass, both locally and in the frontend container.
2. `docker compose up`: `http://localhost:5173` shows the styled health card. With `docker compose stop backend`,
   it shows "Ej tillgänglig" instead of an error page.
3. `http://localhost:5173/finns-inte` shows the styled 404 page with a link back.
4. `npm run generate:types` against the running stack gives no diff on `src/lib/types/api.ts`.
5. A test toast (temporary) appears with Swedish text, then gets removed.
6. CI is green on a pull request. Changing a backend schema without regenerating the types makes the frontend job
   fail on the drift check.
7. The production stack (`docker compose -f docker-compose.yml -f docker-compose.production.yml up --build`) serves
   the styled app on `http://localhost:8080`.
